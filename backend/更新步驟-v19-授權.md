# 客人授權更新步驟（v19）

這次讓安裝版要輸入授權碼才能用。新程式碼完整放在 `backend/程式碼-v19-授權.gs`，整份貼上去取代舊的即可。網址不會變。

這份步驟寫好時，程式還沒發布，也還沒推上 GitHub。請照下面做完，授權才會在正式網址生效。

## 先決條件
- 現在線上是第 18 版（只收 JSON）。v19 是在那一份後面加上授權檢查。
- 只貼 `程式碼-v19-授權.gs` 這一個檔。不要再把 `授權檢查.gs` 加進去，兩個檔有相同的函式，同時存在會發布失敗。
- 不要動 OneDrive 的 Script Properties，也不要改檔案上方的 `FOLDER_ID`。

## 一、建立授權試算表
1. 打開 Google 試算表，新增一份，名稱自訂，例如「玖玖路單授權」。
2. 第一列由左到右打這八個欄名，字要完全一樣：
   - A 客人名稱
   - B 授權碼
   - C 狀態
   - D 到期日
   - E 綁定的電腦識別碼
   - F 啟用日期
   - G 最後連線時間
   - H 備註
3. 第二列可先放一筆自己試用：客人名稱「王先生」、授權碼「JJ-TEST-0001」、狀態「啟用」、到期日「2027-12-31」。E、F、G 先留空。
4. 網址中間 `/d/` 和 `/edit` 之間那一長串就是試算表 ID，複製起來。

欄位怎麼用：
- 狀態只填「啟用」或「停用」。其他文字會被當成停用。
- 到期日用西元，例如 2027-12-31。到期日當天還能用，隔天才鎖。空白不能用。買斷可填遠一點，例如 2099-12-31。
- 綁定的電腦識別碼由程式第一次啟用時自己寫入，不要手打。客人換電腦時，只清空這一欄，啟用日期留著。
- 授權碼不要重複。重複時只用上面那一列。

## 二、備份舊程式碼
1. 打開 Apps Script 專案（script.google.com，用平常的 Google 帳號登入），專案名稱是「百家樂語音」。
2. 左邊每個檔案都點開，全選複製，貼到記事本存成檔案，檔名加上日期，例如 `舊版-程式碼-1120.txt`。
3. 這份備份就是萬一出問題時的退路。線上第 18 版也可以從部署紀錄找回。

## 三、貼上私鑰與試算表 ID
1. 打開本機 `backend/授權私鑰.pem`，整份複製，含開頭 `-----BEGIN PRIVATE KEY-----` 和結尾 `-----END PRIVATE KEY-----`。
2. Apps Script 左邊「專案設定」→「指令碼內容」→「新增指令碼內容」：
   - 屬性 `LICENSE_SIGNING_KEY`，值貼上整份私鑰。
   - 屬性 `LICENSE_SHEET_ID`，值貼上試算表 ID。
3. 私鑰不要貼進程式碼，也不要傳訊息、不要放進 Git。這個檔 Git 會忽略，但仍在這台電腦的專案資料夾裡。請另外複製一份到自己的安全位置。遺失後，已經發出的安裝版不會認得新的私鑰，要重做安裝檔。
4. 對應的公鑰在 `backend/授權公鑰.pem`，已經寫進安裝版。不要改公鑰，除非連安裝版一起重做。

## 四、貼上新程式碼
1. 打開 `backend/程式碼-v19-授權.gs`，全選複製。
2. 在 Apps Script 點「程式碼.gs」，全選舊內容，貼上新內容覆蓋。
3. 如果左邊還有 `road_onedrive`，請刪除（檔案旁的三個點 → 刪除），避免內容重複。不要另建 `授權檢查.gs`。
4. 按上方「儲存」。

## 五、發布新版本（網址不變）
1. 右上角「部署」→「管理部署作業」。
2. 在現有那一筆（類型：網路應用程式）旁按鉛筆「編輯」。
3. 「版本」下拉選「新版本」，說明可寫「v19 授權」。
4. 按「部署」。若詢問 Google 試算表權限，用同一個帳號允許。
5. 不要用「新增部署作業」，那樣會產生新網址，電視版和安裝版就連不上了。

## 六、驗證
發布之後才連得到授權。發布前，現在的第 18 版還不會回答授權檢查。

1. 安裝版開發試用（還沒做新的安裝檔時）：在 `windows-app` 資料夾開 PowerShell，執行
   `$env:ROADMAP_LICENSE_ENFORCE='1'; npm start`
2. 第一次應出現授權碼畫面。輸入試算表裡的授權碼，應進路單。
3. 試算表 E 欄應寫入這台電腦的識別碼，F 欄寫入啟用日期，G 欄有連線時間。
4. 把狀態改成「停用」再重新開啟，應鎖住並顯示「請聯絡業主」。改回「啟用」後，按「重新檢查」可恢復。
5. 把到期日改成昨天，應鎖住。改回未來的日期可恢復。
6. 雲端收件仍照舊：存一次路單，OneDrive「路單收件」要有新的 JSON。

本機已經用假的伺服器測過：第二台會被擋、停用會鎖、過期會鎖、斷網 7 天內可用、超過 7 天會鎖、偽造的通過回覆不被接受。正式試算表的第一次連線，要等你發布之後自己試。

## 七、安裝檔
授權檢查做在安裝版的外殼，不是路單更新檔（.jjupdate）。客人要換成新的安裝檔才會被要求授權碼。

這次沒有幫你做安裝檔。你要發出去時，再自己到 `windows-app` 執行 `npm run dist`。開發時不要設 `ROADMAP_LICENSE_ENFORCE`，舊的測試才會直接開路單。

## 八、網路版密碼（只擋一般人）
網路版網址這次沒有改，也還沒推上 GitHub。推上去之後，公開網址會先問密碼。

- 現在的密碼寫在 `owner-gate.js` 的 `OWNER_PASSWORD`，是 `k4m9-q2vx`。要換就改這一處，再推上 GitHub Pages。
- 本機檔案、localhost、安裝版不會問這個密碼。安裝版問的是授權碼。
- 懂程式的人看得到這段密碼，也能繞過。這只擋一般人。

## 出問題怎麼退回
Apps Script「部署」→「管理部署作業」→編輯 → 版本選第 18 版 → 部署。或把第一步備份的舊程式碼貼回去，再發布一次新版本。
