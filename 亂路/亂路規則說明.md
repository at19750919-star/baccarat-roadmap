# 給 Codex 的任務：亂路（打亂規律）

## 目標
在「百家樂路單」資料夾新增一個獨立網頁工具，產生「看起來沒有好路可打」的莊閒路單，輸出成 .json，可直接用穿越排牌的「目標路單 → 匯入路單」匯入。這個工具跟穿越排牌的排牌邏輯完全無關，只負責產生莊閒序列。

## 範圍限制（必守）
- 只新增檔案，不要修改「百家樂路單」與「ATLL-穿越排牌」任何既有檔案。
- 新檔案：亂路/luanlu.html、亂路/luanlu.js（核心邏輯＋UI，核心邏輯要能被 Node require）、亂路/luanlu.css、tests/test-luanlu.cjs
- 直接用瀏覽器開檔（file://）就能用，不依賴伺服器、不連網、不用外部函式庫。
- 不要 git push。

## 匯入格式
匯入器只看莊閒順序，和局不算，本工具不產生和局。下載檔格式：
{"roads":[{"name":"路單-AT01","nonTieOutcomes":["莊","閒","閒","..."]},{"name":"路單-AT02","nonTieOutcomes":["..."]}]}
值只能是 "莊" 或 "閒"。匯入時同名會覆蓋，所以名稱前綴和起始編號要能調。

## 名詞定義（看大路）
大路一欄 = 同一方連續開出的局數。整條路單寫成欄長序列 L=[L1..Ln]，莊閒交替。
- 單跳欄：長度 1 的欄。
- 紅：連續單跳欄的「欄數」序列（L 中連續的 1 分一組，每組幾欄）。
- 藍：連續「兩顆以上欄」的「欄數」序列（L 中連續的 ≥2 分一組，每組幾欄）。
- **綠**：每個兩顆以上欄的「顆數」序列（單跳不算），**莊、閒分開看**，分成兩條序列：
  - **綠莊**：莊的兩顆以上欄，依出現順序的顆數序列。
  - **綠閒**：閒的兩顆以上欄，依出現順序的顆數序列。
例：L=[1,1,3,2,1,4,2,2,1,1,1]，第一欄是莊（欄依序 莊閒莊閒…）
- 紅=[2,1,3]、藍=[2,3]
- 綠莊 = [3, 2]（第 3、7 欄）
- 綠閒 = [2, 4, 2]（第 4、6、8 欄）

## 硬條件（網頁上可調）
局數（不含和）預設 82；|莊−閒| 上限預設 4；長龍上限（單欄最多幾顆）預設 6。

## 軟條件：規律分數（越低越好，挑最低，不是硬條件）
對紅、藍、綠莊、綠閒四個序列**各自**計分再加總。對序列 S：
1. 相鄰重複：每個 S[i]==S[i+1] 扣 3；連續三個以上相同，每多一個再扣 5。
2. 交替：A B A B（S[i]==S[i+2] 且 S[i]≠S[i+1]）連續 4 個以上，每多一個扣 4。
3. 順序：連續 3 個以上嚴格遞增或遞減且每步差 1（1 2 3、4 3 2），每段扣 3。
4. 週期：長度 2 或 3 的區塊緊接著重複一次（1 2 3 1 2 3），每次扣 4。
5. 某數過多：最常出現的值佔比超過 50%（長度 ≥4 才算），超過的每 10 個百分點扣 3。
整條大路另外：
6. 長段單跳：紅裡任一值 ≥4，每個扣 (值−3)×4。
7. 長段兩顆以上：藍裡任一值 ≥5，每個扣 (值−4)×3。
權重寫成檔案最上面的 WEIGHTS 常數物件。

## 產生方法（建議，可改進但要說明）
1. 隨機產生欄長 1~長龍上限，偏向短欄（約 1:50%、2:25%、3:12%、4:7%、5:4%、6:2%，正規化），第一欄莊閒隨機，最後一欄截斷到剛好等於局數。
2. 不符莊閒差就重抽。
3. 每條跑「嘗試次數」個候選（預設 3000）取最低分，再局部爬山（預設 2000 步）：隨機相鄰欄互換、拆欄、合欄、某欄+1另一欄−1；變動後仍符合硬條件且分數沒變差就接受。
4. 支援種子欄位：有填用可重現亂數（如 mulberry32），沒填隨機。
5. 一次產生多條時，任兩條前 20 局完全相同就重抽。

## 網頁介面
- 輸入：條數(5)、局數(82)、莊閒差上限(4)、長龍上限(6)、名稱前綴(路單-AT)、起始編號(1，補兩位→AT01)、每條嘗試次數(3000)、爬山步數(2000)、種子(空白)。
- 按鈕：產生、下載 JSON。
- 每條一張卡片：名稱、莊/閒局數（如「莊41/閒41」）、總分；大路圖（每欄直排最多 6 列，莊紅圈閒藍圈）；紅、藍、綠莊、綠閒四個序列的數字與各自分數和扣分原因（如「綠莊：相鄰重複×2、交替×1」）；「重抽這條」按鈕。
- 全中文、深色風格，跟現有路單頁一致即可。
- 產生中顯示進度，不要卡死頁面（分批 setTimeout 或 Web Worker）。

## 程式結構
luanlu.js 最後 if (typeof module!=='undefined') module.exports={...}，至少含：toRuns(outcomes)、getSequences(runs, firstSide)→{red,blue,greenBanker,greenPlayer}、scoreSequence(seq)、scoreRoad(outcomes)→{total,red,blue,greenBanker,greenPlayer,road,reasons}、generateRoad(options,rng)、generateRoads(options)、toImportJson(roads)。

## 測試（node tests/test-luanlu.cjs）
1. 範例 L（第一欄莊）的紅、藍、綠莊、綠閒要等於定義的結果。
2. 固定種子產生 20 條：每條 82 局、|莊−閒|≤4、無欄 &gt;6、只有莊/閒。
3. 同種子跑兩次結果相同。
4. 明顯規律的路（全單跳、或 2 2 2 2… 交替）分數明顯高於產生器挑出的路。
5. toImportJson 輸出要能被穿越排牌 target_roadmap.js 的 normalizeRoadEntry 邏輯讀出（在測試裡複製那段判斷：讀 nonTieOutcomes，接受 莊/閒/B/P，濾掉非莊閒，長度&gt;0）。
