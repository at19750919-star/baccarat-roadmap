# 亂路（`luanlu.js`）下三路評分研究與改進報告

## 一、結論摘要（白話總結）

1. **自然隨機狀態下，下三路的紅藍比例其實接近 50% 對 50%（約 49.3% 紅）**：
   依真實百家樂機率（莊 45.86%、閒 44.62%、和 9.52%）產生 500 份 82 局有效莊閒路單，大眼仔、小路、蟑螂路的平均紅比例分別為 **49.45%、49.12%、49.24%**（三路整體平均 **49.27%**），P10～P90 落在 **42.1%～56.4%** 之間；紅比例衝上 65% 的機率幾乎是 **0%（0.0%～1.4%）**，紅藍換色（交替）比例約 **50.6%～50.7%**。
2. **現行版本防不住下三路，有三個根本原因**：
   - **原因 A（預設根本沒算下三路）**：`luanlu.js` 第 10 行預設 `scoreMode: 'big'`，在未手動切換「評分範圍」時，下三路分數標示「未計入總分」（第 379、894–964 行）。此時大眼仔紅比例平均高達 **71.76%**（**94.6% 的路單紅比例 ≥ 65%**），三路最長同色平均 **16.22 顆**（最長達 **42 顆**）。
   - **原因 B（大路「同長行上限」造成結構性偏紅，刪掉紅比例扣分後全面失控）**：預設「單邊同長度行上限 2、合計 3」（`luanlu.js` 第 9 行），限制 2～6 顆的多顆欄合計最多只有 15 欄（實際約 13～14 欄），其餘近 30 欄全都是 1 顆的單跳欄。這會使下三路頂格（`row = 0`）因連續單跳欄同高（`1 === 1`）大量開紅，且第 3 格以上（`row >= 2`）因左方單跳欄「無對無（空對空）」高達 **88%～94% 開紅**。即便切換到 `scoreMode: 'both'`，大眼仔平均紅比例仍高達 **66.56%**（**71.2% 的路單 ≥ 65% 紅**），小路 **58.88%**、蟑螂路 **58.14%**，玩家無腦買紅就有近 6～7 成勝率。
   - **原因 C（只扣「三路最長一段 `M > 6`」引發「一藍假斷紅龍」作弊效應）**：現行 `scoreDerivedRoads`（`luanlu.js` 第 368–370 行）只取三條路裡最長的一段，超過 6 顆才每顆扣 1 分。爬山演算法為了拿 0 扣分，學會**在長紅龍中間每隔 4～6 顆紅球插進 1 顆藍球**（如 `6紅-1藍-5紅-1藍-6紅`）。結果在 `scoreMode: 'both'` 下，大眼仔最長同色雖被卡在 6 顆（87.4% 路單剛好 ≥ 6 顆），但**三路合計長度 ≥ 4 的同色串反而從自然隨機的 13.28 串暴增到 16.79 串**（大眼仔 5.74 串中高達 **5.47 串全是紅串**！），且大眼仔「`≥3紅 + 1藍 + ≥3紅`（一藍假斷紅龍）」平均每份出現 **2.81 次**（自然隨機僅 0.53 次），形成極明顯的「下三路旺紅、逢紅必追」好路。
3. **建議改法效果（500 份實測證明）**：
   將預設 `scoreMode` 改為 `'both'`，並在 `scoreDerivedRoads` 對三條下三路**各自計算再加總**：
   1. **紅比例目標區間（45%～55%）**：偏離 `[45%, 55%]` 部分每 1% 扣 1 分；
   2. **同色串長度分布逐段累進扣分**：每段長度 `> 3`（即 `≥ 4` 顆）的同色串，依超出長度 $d = \text{run} - 3$ 扣 $d(d+1)$ 分（4 顆扣 2 分、5 顆扣 6 分、6 顆扣 12 分）；
   3. **連續單跳（紅藍交替）過長扣分**：連續單跳超過 4 顆時，每多 1 顆扣 2 分（防止演算法為躲避同色串而排出 `紅藍紅藍...` 單跳長龍）。
   - **實測結果**：大路行上限違規率維持 **0.0%**，三路合計紅比例從 **67.22% / 61.28%** 大幅壓低至 **54.47%**（小路 **53.15%**、蟑螂路 **52.87%** 幾乎貼齊自然隨機，大眼仔壓至大路行上限下的物理極限 **57.25%**，紅比例 ≥ 65% 從 94.6% / 71.2% 降至 **0.2% / 0.0% / 0.0%**）；三路最長同色平均降至 **3.85～4.02 顆**（**≥ 6 顆長串佔比 0.0%**）；三路合計長 ≥ 4 同色串從 **16.79 串**大砍至 **5.90 串**（長 ≥ 5 串僅 **0.06 串**）；紅藍交替率穩定在 **51.96%～55.13%**（貼近自然隨機的 50.6%），真正做到「下三路既接近自然紅藍平衡、又完全沒有長串或單跳好路可打」。

     $$B_k = \sum_{c=k+1}^{C-1} \mathbf{1}(L_{c-1} \ne L_{c-1-k}) + \sum_{c=k}^{C-1} \mathbf{1}(L_c > L_{c-k})$$

## 四、建議改法與 `luanlu.js` 修改位置說明（步驟 4）

### 1. 為什麼這樣改？
1. **預設開啟大路＋下三路共同評分（`scoreMode: 'both'`）**：避免預設只算大路而放任下三路出現 15～40 顆長紅龍。
2. **三條下三路各自計分後加總，不再只取單一最長值**：大眼仔看相鄰欄（`offset=1`）、小路看隔一欄（`offset=2`）、蟑螂路看隔兩欄（`offset=3`），大路的某個排列可能只讓大眼仔斷龍，卻讓小路或蟑螂路連紅。三條各自把關才能全面防守。
3. **加回「紅比例目標區間（45%～55%）」扣分**：每條路 `|redRatio - 0.5|` 超過 `0.05`（即紅比例 `> 55%` 或 `< 45%`）時，每偏離 1%（`0.01`）扣 1 分（`derivedRed: 100`）。這會引導爬山演算法將多顆欄與單跳欄交錯排列，最大化頂格高度差與直落突格藍球，把紅比例壓回接近自然隨機。
4. **改用「同色串長度分布逐段累進扣分（`> 3` 即 `≥ 4` 起扣）」**：每條路裡**每一段**長度 $r > 3$ 的同色串，設 $d = r - 3$，扣 $\frac{d(d+1)}{2} \times 2 = d(d+1)$ 分（4 顆扣 2 分、5 顆扣 6 分、6 顆扣 12 分、7 顆扣 20 分）。這能徹底消滅現行「把 12 連紅切為 `6紅-1藍-5紅` 就拿 0 扣分」的假斷龍漏洞。
5. **新增「連續單跳（紅藍交替 `run === 1`）過長扣分」**：當下三路連續單跳超過 4 顆（`derivedAltBase: 4`）時，每多 1 顆扣 2 分（`derivedAlt: 2`），防止演算法為了壓低同色長串而排出 `紅-藍-紅-藍-紅-藍...` 的單跳好路。

function scoreDerivedRoads(outcomes) {
  const big = buildBigRoadGrid(outcomes);
  const marks = {}, sequences = {}, result = {
    total: 0, redRatio: 0, redCount: 0, blueCount: 0,
    longestRun: 0, longestRoad: DERIVED_ROADS[0].key, longestColor: null, marks, sequences
  };
  for (const { key, offset } of DERIVED_ROADS) {
    const roadMarks = buildDerivedRoad(big.grid, offset, big.cols, big.rows);
    const redCount = roadMarks.filter(mark => mark === 'R').length;
    const blueCount = roadMarks.length - redCount;
    const redRatio = roadMarks.length ? redCount / roadMarks.length : 0;
    const run = longestSameColor(roadMarks);
    const runs = derivedRunLengths(roadMarks);
    marks[key] = roadMarks;
    sequences[key] = runs;

    // 1. 紅比例偏離目標區間 [45%, 55%] 扣分
    const redDev = Math.max(0, Math.abs(redRatio - 0.5) - WEIGHTS.derivedRedTolerance);
    let roadScore = redDev * WEIGHTS.derivedRed;

    // 2. 每段超過 derivedRunBase (3) 的同色串累進扣分 + 3. 連續單跳超過 derivedAltBase (4) 扣分
    let singleStreak = 0;
    for (const r of runs) {
      if (r > WEIGHTS.derivedRunBase) {
        const d = r - WEIGHTS.derivedRunBase;
        roadScore += (d * (d + 1) / 2) * WEIGHTS.derivedRun;
      }
      if (r === 1) {
        singleStreak++;
        if (singleStreak > WEIGHTS.derivedAltBase) roadScore += WEIGHTS.derivedAlt;
      } else {
        singleStreak = 0;
      }
    }

    result[key] = {
      redRatio, redCount, blueCount,
      longestRun: run.longestRun, longestColor: run.longestColor, total: roadScore
    };
    result.redCount += redCount;
    result.blueCount += blueCount;
    result.total += roadScore;
    if (run.longestRun > result.longestRun) {
      result.longestRun = run.longestRun;
      result.longestRoad = key;
      result.longestColor = run.longestColor;
    }
  }
  const allCount = result.redCount + result.blueCount;
  result.redRatio = allCount ? result.redCount / allCount : 0;
  return result;
}
